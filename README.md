# RPC 双程耗时分析

内网 RPC 变慢时，值班员上传**同一短窗口**的一批调用记录，网页会回答两个问题：

1. 每笔调用的**请求去程**、**应答回程**各自可能落在哪个耗时区间；
2. 所有调用的两程**能否同时**满足给定的单程耗时上限——从而判断该查去程还是回程。

各主机的时钟并不同步，但同一主机的**钟差在整批内固定**，且两程耗时均须非负。在此模型下：

- 记录彼此矛盾（任何钟差都无法让两程同时非负）→ 提示**复测**，并给出矛盾的约束链及**原表行号**；
- 记录自洽且能同时达标 → 给出满足上限的一组钟差与逐笔两程耗时；
- 记录自洽但无法同时达标 → 给出**能解释这批记录的最小整数微秒上限**，并按一套满足该上限的钟差列出每笔去/回程耗时。

## 快速开始

```bash
docker compose up --build
# 打开 http://localhost:8000
```

网页内置三个试算样例（也可直接上传 `samples/` 下的 CSV）：

- **试算样例**（3 台主机、3 笔调用）：上限填 `200` → 自洽但无法同时达标，最小可行上限为 **225 µs**；改填 `250` → 全部达标。
- **矛盾样例**：单笔记录的两程无法同时非负 → 提示复测并展示矛盾约束链。
- **重复主机对样例**：4 笔调用集中在两台主机、含互相调用，聚合后只上送 **2 条**约束，演示约束条数不随调用数增长。

## CSV 格式

每批最多 **2000 笔**调用、**16 台**主机。表头（列名固定，顺序不限）：

```csv
call_id,caller,callee,req_send,req_recv,resp_send,resp_recv
c1,web1,app1,1000000,1000620,1000700,1000350
```

| 列 | 含义 |
| --- | --- |
| `call_id` | 调用号（允许重复，矛盾定位以原表行号为准） |
| `caller` / `callee` | 调用方 / 服务方主机名 |
| `req_send` | 请求发出时刻（调用方时钟，整数微秒） |
| `req_recv` | 请求到达时刻（服务方时钟，整数微秒） |
| `resp_send` | 应答发出时刻（服务方时钟，整数微秒） |
| `resp_recv` | 应答到达时刻（调用方时钟，整数微秒） |

容忍 BOM、前导空行与字段两侧空白；四个时刻必须是整数（允许微秒级 Unix 时间戳等大整数）。

## 隐私与规模：浏览器侧聚合，服务端只收约束摘要

调用号与四个原始时刻**只留在浏览器**，不上送服务端。浏览器解析 CSV 后，按**有向主机对 (u, v)**
把逐笔差分约束聚合成摘要，每个有向对至多两条边：

- 非负边 `o[v] − o[u] ≤ nn_w`：同方向逐笔权值取**最小**，附胜出约束的原表行号与 leg（去程/回程）；
- 上限边 `o[v] − o[u] ≤ L − lim_delta`（在上限 L 下）：同方向 delta 取**最大**，附出处行号与 leg。

平行差分约束只保留最紧一条与原体系完全等价，因此：

- 上送约束条数 = 出现过的有向主机对数，16 台主机**至多 16 × 16 = 256 条**，不随每对主机的调用数增长；
- 两台主机**互相调用**时 `(a,b)`、`(b,a)` 两个方向各自成条，不会漏约束；同方向桶内可能混入两种
  leg（对端调用的另一程也落在该方向），靠取极值自然合并；
- 自调用（`caller == callee`）汇聚为自环边，差值为负即自相矛盾。

服务端对摘要跑完整判定后返回：可行性、最小可行上限、一套整数钟差、全源最短路界 `bounds`
以及（矛盾时）带行号的负环链。**逐笔可达范围与逐笔耗时在浏览器内**用服务端求出的同一套钟差/界、
套回本地原始时刻计算，口径与服务端纯 CSV 路径完全一致。

## 方法

设主机 `h` 的钟差为 `o[h]`（本地钟读数 = 真实时刻 + `o[h]`，批内固定）。一笔 `a → b` 的记录给出差分约束：

```
去程 = (t2 − t1) − (o[b] − o[a]) ≥ 0     去程 ≤ L
回程 = (t4 − t3) + (o[b] − o[a]) ≥ 0     回程 ≤ L
```

- **自洽判定 / 可行钟差**：Bellman-Ford（差分约束经典解法；约束全为整数，解天然为整数微秒）；
- **矛盾定位**：前驱指针提取负环，环上每条边带原表行号，翻译成可读约束链；调用号重复时仍可按行号定位；
- **逐笔可达范围**：Floyd-Warshall 全源最短路给出 `o[b] − o[a]` 的最紧上下界，浏览器套回逐笔时刻；
- **最小整数上限**：可行性关于 L 单调，二分查找。

## API

### `POST /api/analyze`（原用法保留不变）

请求体 `{"limit_us": 200, "csv_text": "..."}`，服务端解析整份 CSV。

- 200 `{"ok": true, "result": {...}}`：`consistent`、`calls`（逐笔范围）、`feasible_with_limit`、
  `min_limit_us`、`offsets`、`assignment`、`contradiction` 等字段，结构与旧版一致；
- 400 `{"ok": false, "error": "..."}`：输入或 CSV 校验错误（中文提示，含行号）。

### `POST /api/analyze_summary`（网页新用法）

请求体只含约束摘要，不含调用号与原始时刻：

```json
{
  "limit_us": 200,
  "hosts": ["app1", "web1"],
  "constraints": [
    {"u": "web1", "v": "app1", "nn_w": 300, "nn_row": 5, "nn_kind": "ret",
     "lim_delta": 600, "lim_row": 2, "lim_kind": "ret"}
  ]
}
```

服务端校验主机数（≤16）、约束条数（≤主机数²）、主机名归属、行号为正整数等；矛盾响应中的
`contradiction.steps` 为结构化对象（含 `row` 原表行号、`u/v/w/leg`），其余判定字段与原接口同名同义。

另有 `GET /api/health` 健康检查；交互式接口文档见 `/docs`。

  逐笔范围精确值、达标判定、最小上限 225 及 224/225 边界、自调用、非连通主机组、大时间戳、零上限、
  旧 API 冒烟；新增摘要路径等价性、重复主机对聚合极值与行号、互相调用双向不漏约束、
  重复调用号下三角负环按行号 2/3/4 定位、摘要校验（条数上限/坏主机名/重复对/坏行号）、新 API 冒烟。
- 真实启动 `uvicorn main:app` 后 HTTP 端到端验证：
  - 原 `/api/analyze` 在 limit=200 时仍返回 `min_limit_us=225`、钟差 app1=720/db1=0/web1=325，
    逐笔耗时 c1 225/45、c2 0/200、c3 225/225，与改造前完全一致；
  - 新 `/api/analyze_summary` 同批数据给出**完全相同**的钟差与最小上限；请求体仅含主机名、差值、行号，
    经检查不含任何调用号与原始时刻，响应中 `call_id` 为 null；
  - **2000 笔 × 16 主机**满规模（随机数据、调用号故意重复）：浏览器侧聚合 5.5 ms → **240 条**约束、
    请求体 30 KB；服务端分析 63 ms，返回 `min_limit_us=499`；浏览器按同一套钟差重算 2000 笔耗时 2.7 ms，
    全部落在 [0,499]；与旧接口整份 CSV 路径结果逐项一致；
  - 矛盾样例返回结构化负环（合计 −140 µs），行号 2/3/4 与重复调用号 x1 同时给出；
  - 2001 笔、17 台主机、非整数时刻、负上限、超 256 条约束、坏主机名、非法行号均返回 400 中文错误。
- 页面内嵌 JS 提取到 Node 做逻辑测试：CSV 解析/BOM/空行/行号口径、聚合极值与行号、隐私字段不泄露、
  规模上限、矛盾与自洽两套渲染（行号、逐笔耗时 225/45）全部通过；`node --check` 语法通过。

## 待办 / 已知边界

- 模型只假设“钟差固定 + 两程非负”，未校验服务方处理耗时（`resp_send ≥ req_recv`）等额外物理约束；
  如需更严格的复测提示可再加。
- 钟差方案不唯一，展示的是 Bellman-Ford 求出的一组（最小值归零）；如需“最居中”的方案可再做线性规划精调。
- 浏览器侧要求时刻为 `Number.isSafeInteger`（±2^53 以内微秒）；服务端 Python 整数无此限制，
  旧 `/api/analyze` 路径仍可处理更大的时间戳。
- 未做鉴权与请求大小限制，仅限内网可信环境使用；大批量历史追溯、跨窗口钟差漂移建模未覆盖。
- 本环境无 Docker 守护进程，`docker compose up --build` 未在本机实际执行；Dockerfile/compose 未改动，
  为标准 python:3.12-slim + 锁定依赖 + uvicorn 启动，依赖版本与本地实测一致。
